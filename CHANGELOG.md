# Changelog

One generic line per applied lesson or rule change. Newest first.

- 0.2.0-dev (`v0.1.0..v0.2-dev`, up to 2026-11-27): hardening of the guard and the plan gate.
  - Hooks: protected state checked in every repo and cwd; paths and program names compared case-insensitively; gated commands only in the spelling their ask rule matches; `guard.json` written only through `guard-write.sh` / the `guard-apply.sh` gate; symlinks and directory-level copies into the state blocked; a binding to another project never clears one that still holds.
  - Sandbox: user-level settings (no unsandboxed retry, protected state not writable) and a per-project Bash sandbox; only enumerated `gh` / `glab` forms excluded; Claude never runs the installer's writing subcommands; `probe-sandbox.sh` and the TUI dry-run checklist re-check the design per Claude Code version.
  - Push and rename: `git-push.sh` (gate) / `git-rename.sh` run git with the repo's hooks off; plain `git push` / `git branch -m` blocked; the push hook checks a sandboxed verify record (`verify-record.sh`) instead of running commands; the user's git config protected.
  - Plan lock: writes under an open ticket's worktree blocked until `approve-plan.sh` records the hash of the plan shown with `plan-hash.sh`; `approvals/` protected; settings files, the skill dir (exempt only for a session started in the skill repo, `session-record.sh`) and ssh / gh / glab config protected in every session; stage 8 `lock-trace.sh` reports what the lock does not stop.
  - Verify, user-run offer (C11i): when a check hits a known sandbox limit (the next/font TLS check, or an env-dependent check failing the same way on the base because the sandbox hides `.env*`), stage 4 always offers the user-run check - diff stat, the exact command, "run it now, or skip?" - even when the failure is pre-existing; a skip is recorded as "unverified (user declined)", never "ok". The ticket's evidence dir is created at worktree setup, and the env-link message no longer says "not in main checkout" when the sandbox hides the file.
  - Permission mode: ticket sessions run in default mode; auto mode is no longer supported (the hook blocks the Bash per-call parameters `allowed_domains` and `dangerouslyDisableSandbox`, but auto mode may approve other things).
  - Env files under the sandbox (C11h): the project sandbox denies reading `.env*` anywhere in the repo (main checkout, ticket worktrees, `_base`; the user-level `Read(**/.env*)` deny covered only the session's cwd), so builds run without env on both sides of the base comparison; `env-keys.sh <file> --repo <main checkout>` is a bookkeeping script (excluded, allow rule) that prints key names only for a `.env*` file whose realpath lies under the `repo_root` of that project's `guard.json` (the boundary comes from the delivery state, never from `.git` entries on disk; refused before init has written `guard.json`).
  - Reviewer tool rules (C11h): the stage-5 reviewer and the tier-C AC checker are told to stay read-only, use one plain command per Bash call with absolute paths, and run no inline `node -e` / `python3 -c`; what they cannot check that way is reported as unverified.
  - Secret scan and lessons (C11h): `secret-scan.sh` (sandboxed, allow rule) scans a ticket's evidence, diff and untracked files and prints findings masked, replacing a grep that prompted and printed values; the stage-8 `lessons.md` write stays a permission prompt on purpose and is now a named gate (later runs read the lessons).
  - Stage texts without prompts (C11h): the project key in three plain calls (no `$( )`), check output saved by one redirect call with the exit code on stdout, base runs by the tool's directory option (a `cd` out of the ticket worktree is reset), state files read with the Read tool.
  - Push record under the sandbox (C11h): `verify-record.sh` runs turbo commands with `TURBO_CACHE_DIR` set to the worktree's cache; the `Edit` deny rule on `verify.json` is removed (Claude Code merges it into the sandbox, where it refused the record's own write) and the hooks block the file tools on it instead; `apply` removes the old rule.
  - Permission mode enforced (C11h): a new user-level hook (`mode-guard.sh`, every tool) blocks every tool call of a session bound to a ticket outside default mode or with no `permission_mode` in the hook payload; the skill's scripts are blocked in any session outside default mode; stage 0 check 1c stops. The eval runner's auto mode is blocked too (open item).
  - Fewer prompts that are not gates (C11a-c): user-level file-tool rules (Read of the skill and the state root, Edit of `tickets/` and `evidence/`, Edit denied on the protected state and `verify.json`); one skill script per Bash call, checked by the docs lint; Edit allowed in ticket worktrees (an ask for `_base`, worktree config and agent instruction files); `sandbox.autoAllowBashIfSandboxed` set by `project-sandbox-apply`; turbo runs with a worktree-local `--cache-dir`; `base-worktree.sh` is a bookkeeping script with validated arguments.
  - Commits under the project sandbox (C11): the git ref store and git files that unsandboxed git reads are denied to sandboxed commands; commits go only through `git-commit.sh` (the gate); `git commit` and `pnpm add|install` are accepted only in the spelling their ask rules match.
  - Verify under the sandbox (C11c4): a `next/font/google` build that fails on the sandbox's TLS check is reported as a known sandbox limit, never "build ok"; the build then runs as user-run evidence after you review the diff. A user-run paste never updates the push record.
  - Code Mode is not supported: stage 0 stops and the hooks deny the `REPL` tool and block the skill's scripts while it is on.
  - Docs: README rewritten for a new reader (requirements with a tested / not tested table, quick start, ticket flow, safety model, known limits, troubleshooting); long safety detail moved to `docs/safety.md`; `docs/sandbox-dry-run.md` covers the 1c checks. Probed baseline: Claude Code 2.1.325; re-run the probe pass before moving to a newer version.
  - Commits (C11e2): `git-commit.sh` logs the commit's own tree and file list (renames as delete + add) and exits 3 with a `MISMATCH` line when the commit is not what was staged; stage 7 shows `git diff --cached --stat=10000 --no-renames` right before it, and stage 8 `lock-trace.sh` compares that stat, the log line and the repo per commit (a trace, not proof).
  - Excluded scripts (C11e3): gate and bookkeeping wrappers run `#!/bin/bash -p` and start python3 from a fixed list under `env -i` with only `SSH_AUTH_SOCK`, `LANG` / `LC_*` and `DELIVER_TICKET_HOME`; PATH fixed and HOME from the password database; the hook refuses wrappers / env assignments / nesting on bookkeeping scripts too. Defense in depth: Claude Code 2.1.325 already ran PATH-changing compound forms sandboxed (probe).
  - Build process: a dev clone for building the skill; every test suite warns when it runs against the live checkout.
- 0.1.0-dev: skeleton and SKILL.md (phase 1).
